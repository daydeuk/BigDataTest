### 11/27 채점 — ✅ 통과 (test macro F1 0.6686), 고칠 곳 2개

| 단계 | 결과 | 메모 |
|---|---|---|
| 1 탐색 | ✅ | `value_counts()`로 3종류 → **분류** 판단 👍 |
| 2-1 나누기 | ✅ | `X_test = test.drop(...)` 👍 |
| 2-2 결측 | ❌ | **`avg_basket`을 `X['age'].mode()[0]`로 채움** → 장바구니 금액 빈칸에 **42**(나이 값)가 들어감. 원래 값은 8,000~ (중앙 52,200) |
| 3-1 인코딩 | ✅ | **합쳐서 `columns=`** — test에만 있는 '세종' 함정 통과 👍 |
| 4-1 분할 | △ | **`stratify=y` 빠짐** ⚠️ 반복 (Day 4) — 검증 등급 비율이 틀어짐 |
| 4-3 예측 | △ | 다중 분류에 `predict_proba(...)[:, 1]` — 의미 없는 줄 (아래 AUC 에러의 원인) |
| 4-4 점수 | ✅ | `average='macro'` 👍 |
| 5 제출 | ✅ | `predict` + `index=False` + (400, 1) 👍 "f1이니까 pred 제출!!!" 주석 정확 |

**avg_basket을 고치면** test macro F1 0.6686 → **0.6786** (실행 확인). 기준을 넘었어도 이런 줄 하나가 점수를 깎는다.

```python
m = X['avg_basket'].median()                       # ← 채울 컬럼과 같은 컬럼에서 값 구하기
X['avg_basket'] = X['avg_basket'].fillna(m)
X_test['avg_basket'] = X_test['avg_basket'].fillna(m)
```

> 값을 구하는 줄(`m = X['…']`)까지 **세 줄 모두 같은 컬럼 이름**인지 확인 — 이번 실수는 Day 4 복습의 "한 줄 안 컬럼 이름"이 **줄 사이**로 번진 것

**`**` 질문 답**

| 질문 | 답 |
|---|---|
| `roc_auc_score` 에러 원인? | 정답이 **3종류(다중 분류)** 라서. `predict_proba`가 열 3개(Bronze, Gold, Silver 순)를 주는데 `[:, 1]`로 Gold 확률만 넣음 → `ValueError: multi_class must be in ('ovo', 'ovr')`. 다중 분류 AUC는 `roc_auc_score(y, model.predict_proba(X), multi_class='ovr')` (전체 확률 표를 넣음) → 0.8637. **이번 지표는 macro F1이라 AUC는 필요 없다** |
| 0.67이면 괜찮은가? | 정해진 기준 없음. **전부 Bronze로 찍으면 0.21** → 3배 이상이니 잘 배운 것. "0.5~0.75"는 기준이 아니라 Day 4 데이터에서 본 범위 — 점수는 데이터가 정한다 |
| coupon_use: '없음' vs 'Y'(최빈)? | 둘 다 OK (Day 4에서 비교: 차이 거의 없음) |
| age 평균 / basket 중앙값 판단 | 둘 다 OK — 문제가 지정 안 하면 자유. 판단 근거를 주석으로 남긴 게 좋다 |
| 다중 분류에서 `predict_proba()[:, 1]`? | 열이 등급 수만큼(3). `[:, 1]`은 Gold 확률 하나뿐 → 의미 없음. **다중 분류 = 거의 macro F1 = `predict`만**, proba 제출할 일 거의 없음 |

### 재검토 (고친 뒤) — ✅ test macro F1 0.6684

| 고친 것 | 확인 |
|---|---|
| `stratify=y` 추가 (`strartify` 오타도 고침) | 검증 등급 107 / 84 / 49 = 전체 비율 그대로 ✅ |
| `m = X['avg_basket'].mode()[0]` | 채운 값 53,400 ✅ (같은 컬럼에서 구함) |
| 4-3의 proba 줄 삭제 | ✅ |

남은 정리: 5-2의 `proba = model.predict_proba(X_test)[:, 1]` 줄도 지우기 (안 쓰는 줄) / 주석 "분할이니까" → **"분류니까"** / 주석 "중앙값이 유리"인데 코드는 `mode()` — 둘 중 하나로 맞추기

### 라벨 인코딩 버전 — ✅ test macro F1 0.6728 (2026-11-27)

```python
all_x = pd.concat([X, X_test])
cols = ['gender', 'region', 'coupon_use', 'app_user']
for c in cols:
    le = LabelEncoder()                       # 매번 새로
    all_x[c] = le.fit_transform(all_x[c])
X = all_x.iloc[:len(X)]
X_test = all_x.iloc[len(X):]
```

| 확인 | 결과 |
|---|---|
| shape | (1200, 10) / (400, 10) — 원핫(20열)과 달리 컬럼 수 그대로 ✅ |
| 글자 컬럼 남음 | 없음 ✅ |
| **test에만 있는 '세종'** | **6**으로 변환 ✅ (합쳐서 fit했기 때문 — train만 fit했으면 `unseen labels: '세종'` 에러) |
| 점수 | 원핫 0.6684 vs **라벨 0.6728** — 비슷 (둘 다 OK) |
| proba 줄 | 3군데 모두 주석 처리 + "다중 분류는 proba 사용 X" 메모 ✅ |

### 원핫 vs 라벨 — 정말 라벨이 더 좋은가? (random_state만 바꿔 5번 비교)

| 모델 `random_state` | 원핫 | 라벨 | 더 높은 쪽 |
|---|---|---|---|
| 42 | 0.6684 | 0.6728 | 라벨 |
| 1 | **0.6746** | 0.6717 | 원핫 |
| 7 | 0.6519 | 0.6810 | 라벨 |
| 100 | 0.6620 | 0.6797 | 라벨 |
| 2026 | 0.6690 | 0.6747 | 라벨 |

> 이 데이터에선 라벨이 약간 유리한 편 (5번 중 4번). 하지만 **무작위만 바꿔도 0.03씩** 움직여서 인코딩 차이(0.004)보다 크다. Day 5 회귀에선 원핫이 조금 좋았다 → **정해진 승자 없음**
> 결측 한 줄 실수 −0.01, 0/1 대신 확률 제출 −0.1 → **인코딩 선택보다 실수 안 하기**가 훨씬 크다
> 고르는 법: 시간 빠듯 → 원핫 / 값 종류가 아주 많은 컬럼 → 라벨 / 문제가 지정 → 그대로

| | 결과 |
