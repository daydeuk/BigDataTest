## 2. 5단계 한 장 (번호 = 단계-조각)

```
1 탐색       1-1 불러오기 · 1-2 훑어보기 (shape, isnull, 정답 비율 — test 행 수 기억!)
2 전처리①    2-1 나누기 (y / X / X_test) · 2-2 결측 (train 기준, 둘 다)
3 전처리②    3-1 인코딩 (concat([X, X_test]) → get_dummies → iloc으로 다시 나누기)
4 모델링     4-1 분할 · 4-2 학습(fit) · 4-3 예측 · 4-4 점수 (정답 먼저)
5 제출       5-1 다시 학습 fit(X, y) · 5-2 저장 (X_test, index=False) · 5-3 확인 (행 수 = test)
```

| 평가지표 | 예측 | 제출 |
|---|---|---|
| **ROC-AUC** | `predict_proba(X)[:, 1]` (확률) | 확률 |
| **F1 · accuracy** | `predict(X)` (0/1) | 0/1 |

| 3-1 인코딩 | ✅ (고친 뒤) | `cc` → `all_x` 이름 바꾸고 두 군데 남음 (NameError), `iloc[:, 1000]` 쉼표 |

| 5-3 확인 | — | (200, 1)이 나왔는데 지나침 → test 행 수 300과 비교했어야 |

### ⭐ 어려웠던 것 ① — 결측 채우기 4가지 모양 (실행으로 확인)

| 모양 | 결과 |
|---|---|
| `X[X['age'].isnull()] = m` | ❌ 그 행의 **모든 컬럼**이 41로 (gender·region까지). payment 줄에서 `FutureWarning: incompatible dtype` |
| `X[X['c'].isnull()]['c'] = m` | ❌ **아무것도 안 바뀜** + `SettingWithCopyWarning` (Day 1 체인 대입) |
| `X.fillna(m)` | ❌ **표 전체** 빈칸이 41로 → total_spend도 41, payment도 41.0 |
| `X['c'].loc[조건] = m` | ⚠️ 지금은 바뀌지만 `FutureWarning` — 앞으로 안 됨 |
| **`X['c'] = X['c'].fillna(m)`** | ✅ 추천 |
| **`X.loc[X['c'].isnull(), 'c'] = m`** | ✅ |

> **한 줄 안에 컬럼 이름이 두 번 — 둘이 같아야 한다**: `X['payment'] = X['payment'].fillna('없음')`
> 처음 실수 때 `X.loc[X['total_spend'].isnull(), 'age']`처럼 열 자리가 달라서 test 고객 나이가 1,843,150살이 됨
> 확인은 `isnull().sum()`만으로 부족 → `value_counts()` · `describe()`로 **들어간 값**까지 본다

### ⭐ 어려웠던 것 ② — `iloc[:1000]` vs `iloc[:, 1000]`

| 코드 | 뜻 | 결과 (1300 × 19) |
|---|---|---|
| `iloc[:1000]` | 행 0~999 | (1000, 19) ✅ |
| `iloc[1000:]` | 행 1000~끝 | (300, 19) ✅ |
| `iloc[:, 1000]` | 모든 행의 **1000번 열** | 💥 IndexError (열은 19개) |

> 행만 자를 땐 **쉼표 없이**. `:` 뒤 숫자 = "여기까지", 숫자 뒤 `:` = "여기부터"

### ⭐ 어려웠던 것 ③ — 제출 단계에서 어떤 X?

| 단계 | 함수 | 넣는 것 | 행 |
|---|---|---|---|
| 4-2 | `fit` | `X_train, y_train` | 800 |
| 4-3 | `predict` | `X_value` | 200 |
| 5-1 | `fit` | `X, y` (선택: 800명 그대로도 통과 0.7488, 다시 학습 0.7579) | 1000 |
| 5-2 | `predict` | **`X_test`** (필수) | **300** |

> **5단계에 `X_value`·`y_value` 글자가 보이면 안 된다.** 5-3에서 행 수 = 1-2에서 본 test 행 수

### ⭐ 어려웠던 것 ④ — 지표 → 예측·제출 방식

| 지표 | 뜻 | 예측·제출 |
|---|---|---|
| ROC-AUC | 이탈 고객에게 더 높은 확률을 줬나 | `predict_proba()[:, 1]` 확률 |
| F1 (macro) | 드문 쪽(이탈)을 놓치지도 헛짚지도 않았나 | `predict()` 0/1 |
| accuracy | 전체 중 몇 % 맞혔나 | `predict()` 0/1 |

> 불균형(이탈 10%)에서 전부 0이라 찍으면 accuracy 0.90인데 macro F1 0.47 — F1은 적은 쪽을 본다
> 시험에선 **지표를 문제가 정해 준다** → 이름 그대로 쓰고 예측 방식만 맞추면 된다

### 그 밖에 나온 것
- `NameError: name 'cc' is not defined` = 만든 적 없는 변수. 에러의 **`line 57`** 로 바로 찾기 (맨 아래 에러 종류 → 바로 위 줄 번호)
- `# churn → 0/1 (회귀 문제)` ❌ — 0/1은 **분류**. 회귀는 값이 제각각
- payment 결측을 '없음' vs 최빈값('카드'): 점수 차이 거의 없음 (F1 0.7579 vs 0.7660) — 둘 다 OK
- LabelEncoder vs get_dummies: 랜덤포레스트에선 둘 다 OK (0.7463 vs 0.7579). 문제가 "라벨 인코딩"이라 할 때만 LabelEncoder
- age를 최빈값(41)으로 채우니 검증 F1이 0.7453 → 0.7679 — 방법에 따라 점수가 이만큼 움직인다
